# PlexonShops 2.3.0

PlexonShops 2.3.0 migrates the plugin to the stable PlexonCore 2.0.0 API while preserving the optimized 2.2 shop, teleport, persistence, cache, GUI, economy, PlaceholderAPI, and public-event behavior.

## Core 2 integration

- Compile/runtime compatibility updated to PlexonCore 2.0.0.
- Core API 1.x remains recognized as `CORE_LEGACY`; API 2.x is `CORE_RUNTIME`.
- Core 2.0.0 currently has no public movement/damage/join/quit subscription contracts, so those event families intentionally keep the proven local listener path.
- Runtime ownership is explicit in `/pshops diagnostics`; Core module registration is not misreported as Core-owned player events.
- `AUTO`, `CORE`, and `LOCAL` ownership requests are supported, with fail-closed behavior when required local fallback is disabled.

## Teleport pipeline

- Movement, damage, and quit processing now converge on source-independent fact methods in `TeleportService`.
- The no-pending movement path remains an O(1) UUID map gate.
- Rotation-only, final-cancellation, cross-world, epsilon, fee/refund, cooldown, bossbar, async teleport, and visit-event semantics are preserved.
- Added low-overhead player-event counters to diagnostics.

## Build and release integrity

- Paper 26.2 / Java 25.
- Core 2.0.0 CI dependency is pinned by SHA-256.
- Distribution verification checks the Core runtime bridge and rejects shaded PlexonCore classes.
- Stable release assets are immutable; an existing release is never overwritten with `--clobber`.

## Data compatibility

No destructive SQLite migration is introduced. Existing shop UUIDs, public API/events, commands, permissions, Vault behavior, and PlaceholderAPI behavior remain compatible.

## Upgrade / rollback

Replace the previous plugin JAR and restart the server. Existing configuration remains valid; the new `core-runtime` section uses safe defaults when absent.

Rollback target: PlexonShops 2.2.0. No database downgrade step is required by this release.
