# PlexonShops 3.0.0-rc.1

Phase 2 release candidate. Stable promotion is intentionally blocked until PlexonCraft runtime certification.

## Highlights

- discovery-first `/pshops` hub and compact shop review profiles
- cached browse, category search, favorites, featured shops and bounded recent visits
- authoritative availability resolver shared by GUI and teleport paths
- identity-bound warmup → in-flight teleport lifecycle that rejects duplicate attempts and stale async callbacks
- at-most-once Vault charge/refund ownership and post-success-only visit publication
- discovery cache generation checks that discard stale asynchronous results after mutation, deletion, unload or directory revision changes
- versioned additive SQLite schema with pre-migration 2.2.1 backup
- fail-closed rejection of database schemas newer than supported schema 3, before migration/DDL/marker writes
- strict candidate configuration validation and transactional reload rollback
- actor/action/shop/revision-bound two-stage destructive confirmation
- expanded cache-only PlaceholderAPI and immutable public discovery API
- administration profiles with feature/status controls and teleport diagnostics
- exact-head and exact-tag Java 25/class-major 69 distribution, test, checksum and provenance gates

## Compatibility and rollback

Published rollback boundary: `v2.2.1` at `81c77e936194de2d46fd40221ea57a1f65c07b34`.
Existing shop UUIDs, owners, names, descriptions, locations, ratings, visitor statistics, labeled items and Vault economy ownership are preserved.

Schema 3 migration is forward-only for the candidate. Restore the saved 2.2.1 data backup before rollback testing. A database advertising a schema newer than 3 is rejected without being downgraded or rewritten.

## Runtime certification

Not executed for this prerelease. Do not promote to stable until the documented PlexonCraft runtime gates pass, including migration, discovery/browser behavior, owner controls, teleport cancellation/idempotency, Vault/Theosis compensation, stale discovery-load rejection, restart/reload behavior, PAPI/API/Core integration, Spark/MSPT comparison, a 30-minute-or-longer soak, and zero HIGH/CRITICAL defects.
